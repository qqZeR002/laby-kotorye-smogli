## Черновик, который разбирали

```python
from datetime import datetime


def check_sla(bug):
    """Критичный баг без обновления больше 3 дней получает флаг."""
    if bug["priority"] == "critical":
        days = (datetime.now() - bug["updated_at"]).days
        if days > 3:
            return True
    return False
```

Первый прогон тестов на черновике: `1 failed, 5 passed`. Упал тест на границу (ровно 3 дня).

## От чего отказались как от лишнего

- Класс `Bug` на `dataclass` и перечисления `Enum` для приоритетов и статусов. Для одной функции с одним правилом это лишнее, оставлен обычный словарь.
- Библиотеку `freezegun` для «заморозки» времени в тестах. Не нужна: после того как `now` стал параметром, время подставляется обычным аргументом, без сторонних пакетов.
- Учёт рабочих дней и выходных. В постановке этого нет, правило про календарные дни.

## Безопасность

Модуль не работает с сетью, файлами и вводом пользователя, поэтому уязвимостей вроде инъекций здесь нет. Единственный внешний ввод — аргумент N в `main.py`; при нечисловом значении программа завершится с ошибкой `ValueError`.

## Повторная проверка

Я прочитал отчёт выше и попросил перепроверить пункты 2, 5, 6 и 10. Конкретных ошибок я не называл, только указал, какие пункты проверить ещё раз. Агент заново прогнал по ним пограничные случаи. Результат:

| Пункт | Что проверяли | Что нашлось | Что сделано |
|-------|---------------|-------------|-------------|
| 2 (время) | остались ли скрытые вызовы `datetime.now()` | ничего. В `sla.py` один вызов, только как значение по умолчанию в `flag_bugs` | без изменений |
| 5 (статусы) | статусы, которых нет в списке | **ошибка.** Баг со статусом `Closed` (с большой буквы), `wontfix`, пустой строкой или `None` молча получал флаг | неизвестный статус даёт `ValueError` |
| 5 (статусы) | баг без поля `status` | **несогласованность.** Критичный баг без `status` давал `KeyError`, а некритичный молча возвращал `False` | все поля читаются до проверок, `KeyError` при любом приоритете |
| 6 (время) | перевод часов | **ошибка.** Если оба времени в одном часовом поясе (например, `Europe/Warsaw`), Python вычитает показания «стенных» часов. 25.10.2026 реально прошло 24:30, а код насчитал 23:30 и не поставил флаг. Весной наоборот: прошло 23 часа, флаг поставлен | оба времени переводятся в UTC перед вычитанием |
| 6 (время) | время не `datetime` | **непонятная ошибка.** Для даты строкой (так она приходит из JSON) было `AttributeError: 'str' object has no attribute 'tzinfo'` | понятный `TypeError` с названием поля |
| 10 (список) | порядок, копии, генератор, сломанный баг в списке | ошибок нет. Порядок сохраняется, возвращаются те же объекты, генератор принимается. Сломанный баг останавливает весь список с `KeyError` — это следствие пункта 8, оставлено намеренно | добавлены тесты, которые это закрепляют |

Последствие для пункта 9: раз неизвестный статус теперь ошибка, то и неизвестный приоритет должен быть ошибкой. Иначе `Critical` с большой буквы молча остаётся без флага, а это хуже лишнего флага: просроченный критичный баг никто не увидит. Прежнее решение «не менять» отменено.

Прогон новых тестов до исправлений: `14 failed, 49 passed`. После исправлений: `63 passed`.

### Тестовые случаи

Мой случай: **баг обновили час назад, N = 1**. Ожидание: флага нет. Код проходил его и до исправлений, тест добавлен как `test_updated_hour_ago_with_n_1_no_flag`.

### Вывод

Первое ревью нашло то, что просило задание (хардкод N и время), и на этом остановилось. Ошибка с переводом часов не видна при чтении кода и не ловится тестами с фиксированным временем в UTC: нужен тест именно с часовым поясом, где есть перевод часов.
